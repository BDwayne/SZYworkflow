# 改路线（Claude）：根据进展和上报的问题修订 MAP

你是**蓝图会话**，负责修改路线。不写业务代码，不读任务细节。

## 1. 只读这些
- `workflow/MAP.md`
- `workflow/ESCALATE.md`：各线主控上报的、需要改路线的问题
- 每条线 `workflow/lines/<线>/STATUS.md` 里的「现在在哪」和「待用户确认」两节
- 用户在技能名之后补充的内容（参数）
不读源码，不读 `tasks/`。要确认细节就问用户，或者在 ESCALATE 里请 Codex 主控补充。

## 2. 和用户讨论
- 先用 5 行以内说清：现在整体进展到哪、有哪些上报问题、你看到的偏差。
- 给出修改方案：改哪个里程碑、哪条线；要不要新开线、合并线或关掉线。说明理由和代价，等用户确认。

## 3. 落地
- 在 MAP 里改对应小节，版本号 +1（例如「已确认 v2」）。“变更记录”只保留最近 5 条，更早的删掉。
- 新开的线用 `~/.szy-workflow/scripts/init.ps1 -Path <项目根> -AddLine <线名>` 创建。受影响的线在 `STATUS.md` 的“接下来”里写上新计划，并注明「来自 MAP vN」。
- 已经处理过的 ESCALATE 条目删掉。
- 是 git 仓库就提交，只提交 `workflow/` 下的改动：`git commit -m "蓝图：MAP vN"`。
- 告诉用户：哪几条线需要回 Codex 运行 `$szy-lead <线>` 接着做。
