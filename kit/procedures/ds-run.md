# 自动化执行（DeepSeek）：照着 runbook 做，不自由发挥

你是**自动化执行会话**。参数是任务编号（如 `dev-T012`）。

1. 读 `workflow/tasks/active/<编号>-*.md`。如果「执行者」不是 `ds`，或者没有写 runbook 编号：停止，告诉用户这个任务应该交给 Codex。
2. 读该任务引用的 `workflow/runbooks/Rxx-*.md`。如果 runbook 的状态不是「已验证」：停止，告诉用户。
3. 只读这两个文件，以及 runbook 里点名要读的文件。不浏览源码，不读其他文档。
4. 开工前运行 `git status`。工作区不干净：只提醒用户，不要动别人的改动。
5. 按 runbook 的步骤，用任务说明里给的参数**逐步**执行。每一步都运行它给的检查命令。
   - 结果和预期不一致，或者遇到 runbook 里没写的情况：**立刻停止**。不要尝试修复，不要换别的办法，也不要改脚本。
   - 批量任务：某一组参数失败了，记下来，跳过，接着做下一组。runbook 里写了“失败即全停”的除外。
6. 收尾按 `workflow/.szy/procedures/handoff.md` 执行。交接要短：
   - 结果：完成 / 部分完成 / 受阻
   - 成功和失败各几组；失败的那组参数和原始错误信息（只贴最关键的几行）
   - 「可固化」不用填；遇到受阻时，「给主控的建议」写“建议改派 codex 处理”
